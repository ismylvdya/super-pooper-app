# SuperPooper для iPhone

Рабочий проект — этот репозиторий. List Lab физически лежит внутри него в папке `list-lab/` со своим локальным Git. Это песочница, а её пакет `list-lab/ListEngineChumbulev` — зависимость основного приложения. Ссылка `../list-lab` ведёт на эту же папку через симлинк, чтобы работал существующий путь к пакету в `SuperPooper.xcodeproj`. Перед работой над списками проверь состояние Git в обоих репозиториях.

## Git для List Lab

Изменения движка коммить в локальном репозитории List Lab. Команда «пушь» для SuperPooper относится только к репозиторию приложения. Для List Lab не нужен удалённый репозиторий, и его коммиты не отправляются на GitHub. Правило `/list-lab/` в корневом `.gitignore` исключает папку из обычного добавления файлов SuperPooper. Не добавляй её принудительно или как сабмодуль.

## Где искать поведение

- Запуск проходит через `App/SuperPooperApp.swift` → `AppContainer` → `RootView`. Контейнер собирает зависимости, Router и TabStack отвечают за навигацию. Экраны в `Features/` читают состояние и вызывают команды через фасад `AppModel`. Его части в `App/State/` отвечают за запись задач, источники, день, синхронизацию и публикацию производного состояния.
- Today объединяет пул дел без времени и таймлайн. Для вопроса «почему дело здесь?» начни с `Domain/Day/DayBuilder.swift`, `Building/` и `Sections/`. Для вопроса «что записалось после переноса?» проследи вызов из экрана через `AppModel`, `App/State/Day/` до `Data/TaskFile/`. При расчётах используй внедрённые Clock, календарь и границу дня из DayContext.
- Day spreader разбирает сегодняшний или завтрашний день (`Features/MorningReview`). Горизонты и проекты — `Features/Lists` и `Domain/Lists`. Редактор и подзадачи — `Features/TaskPage`. Правила отметок привычек и повторения вынесены в `Domain/Habits` и `Domain/Recurrence`.
- Calendar и Reminders подключены через `Data/EventKit`. Для уведомления проверяй отдельно расчёт в `Domain/Notifications`, очередь в `App/State/Derived`, системный адаптер и обработку ответа в `App/Notifications`. Виджеты Today, Habit и Clock находятся в `Widgets/`; общие данные и снимки — в `Core/Storage` и `Core/Widgets`.

## Данные пользователя

Контракт описан в `docs/BACKEND.md`, синтаксис задаёт `Resources/Config/task-file.json`. В выбранной папке Obsidian открытые задачи живут в `Task Manager/Tasks.md`, завершения — в `Done.md` рядом с ним, настройки привычек — в `Habits settings/`. Пользователь может менять Markdown вручную. При правках формата учитывай оба направления чтения и записи, старые файлы, миграции и резервные копии. При выборе посторонней папки без Task Manager приложение оставляет её нетронутой.

Раздел задаёт горизонт, дата задаёт срок, метка `in_today_pool` включает строку в пул. Порядок строк Next actions задаёт порядок пула и разбора. Проект — родительская задача с маркером проекта. Это важно при переносе семьи, смене секции и появлении новой строки привычки. Исторические описания TaskNotes в справочнике и `reference/tasknotes/` относятся к прежнему хранилищу.

## Движок списков

Общие правила работы и оформления списков реализуй в пакете `list-lab/ListEngineChumbulev`. Например, движок вычисляет стандартный отступ и предоставляет параметр для отдельной строки. SuperPooper подключает пакет, передаёт состояние задачи, иконку и нужное переопределение. Если пакет недоступен для записи, запроси доступ к List Lab перед изменением общей логики.

- В песочнице точка входа для SwiftUI — `ReorderableList`. За UICollectionView, жесты, удержание, подъём, автопрокрутку и приземление отвечают `ListController` и компоненты пакета. Общее поведение меняй там. Демо и его тема `list-lab/Resources/list-looks.json` позволяют воспроизвести жест отдельно от данных задач.
- В приложении `Features/Common/ListEngine/` связывает движок с меню, действиями и созданием задач. `Features/Today/TasksCarry.swift` связывает списки при переносе между ними; у таймлайна собственный обработчик drop. Экран передаёт намерение в AppModel, который меняет задачи и их порядок. Тема приложения — `Resources/Config/list-theme.json`. При изменении схемы темы проверь оба JSON.
- Для регрессий с вложенностью проверь пул, backlog, Lists, разбор и страницу родителя. D-197–D-199 в `DECISIONS.md` описывают интеграцию, выход задачи на верхний уровень, самоподбор высоты и вид строки при приземлении.

## Правила и проверка

Следуй `CLAUDE.md`: чистая логика в Domain, файловые и системные операции за адаптерами. Внешний вид, действия, правила и значения по умолчанию задаются в `Resources/Config/`, строки интерфейса — в `Localizable.xcstrings`. Интерфейс и комментарии на английском, документация на русском. Основной Xcode-проект использует синхронизируемые группы. У песочницы свой `project.yml` и XcodeGen.

Из корня приложения:

```sh
scripts/xcb.sh build
scripts/xcb.sh test -only-testing:SuperPooperTests
scripts/sim.sh load-vault && scripts/xcb.sh test -only-testing:SuperPooperUITests
```

Для движка — `list-lab/scripts/lab.sh test`, для ручной проверки жеста — `list-lab/scripts/lab.sh run`. Имя симулятора по умолчанию — «🌭 iPhone 13 mini», переопределяется через SP_SIMULATOR у приложения и LAB_SIMULATOR у песочницы. Проверяй запись задач на Fixtures/TestVault. Завершённые изменения коммить в соответствующем репозитории. Push и релиз SuperPooper — по команде владельца.

`docs/HANDBOOK.md` помогает найти подсистему, `DECISIONS.md` объясняет решения владельца. Если старое описание расходится с реализацией, сверяй последнее решение по теме, актуальный код и тесты.
