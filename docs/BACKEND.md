# Бэкенд: один файл задач

С ноября 2026 приложение работает не на заметках TaskNotes, а на своём простом формате по образцу плагина Макса (`kudrmax/obsidian-task-tracker`). Папка `TaskNotes` в vault не трогается: приложение её только читает, и только когда вы сами нажимаете импорт. Это ваш бэкап.

## Где что лежит

В настройках выбирается папка `SuperPooperApp`. Приложение видит только её и **ничего не создаёт, если внутри нет `Task Manager`**: так случайно выбранная папка (или старая `TaskNotes`) остаётся нетронутой.

```
SuperPooperApp/
  super-pooper-app-settings.json     настройки приложения
  Task Manager/
    Tasks.md                         все задачи и дни привычек
    Habits settings/
      a1b2c3d4.json                  настройки одной привычки
      Trash/                         удалённые привычки
```

Имена, заголовки разделов, галочки и значки — в `Resources/Config/task-file.json`, в коде их нет.

## Tasks.md

```markdown
## Inbox
## Now
- [ ] Побриться 📅 2026-11-04 ➕ 2026-11-01 🆔 bf46c871
### Morning
- [ ] 🚿 Холодный душ 🌅 morning 🆔 a9fc7aff
- [/] Написать отчёт 📅 2026-11-04 ⏰ 14:00 ⏳ 60 🔥 🐸 🆔 29b3f293
    Текст задачи — строки с отступом.
    - [ ] Подзадача 🆔 77aa01bc
## Soon
- [ ] Отменить Sigma 📅 2026-11-05 🔥 🆔 8dfae0e6
## Half year
## Someday
## Waiting
## Done
- [x] Вазелин ✅ 2026-11-03 🆔 0e11eb64
- [x] 🏋️ Отжимания ✅ 2026-11-03 🆔 2e47c3dc
## Archive
## Trash
- [ ] Старое 🗑️ 2026-11-02 🆔 11223344
```

- **Раздел = уровень планирования.** `## Now` и `## Soon` — это «эта неделя», остальные как называются. Перенос в приложении переносит строку, перенос строки руками в Obsidian меняет статус.
- **Галочка:** `[ ]` открыта, `[/]` начата, `[x]` выполнена.
- **Поля — в конце строки**, каждое со своим значком: `📅` дата, `⏰` время, `🌐` часовой пояс (обычно пусто), `⏳` длительность в минутах, `🔥` high priority, `❤️` приятно, `🐸` требует энергии, `🌅` рутина, `🔼` родитель (если подзадача лежит в другом разделе), `➕` создана, `✅` выполнена, `🗑️` удалена, `🆔` id. Значок внутри названия остаётся названием: поля читаются только с конца строки.
- **Одно свойство даты вместо `due`.** Есть просто дата и просто время.
- **Подзадачи и текст** — строки с отступом под задачей.
- Всё остальное в файле (другие разделы, посторонние строки) сохраняется как есть. Строке, написанной руками без `🆔`, id присвоится при следующем чтении.

### Смена дня

При чтении файла незавершённая задача из `Now`/`Soon` с датой раньше сегодняшней получает сегодняшнюю дату и теряет время (и часовой пояс): она оказывается в пуле. «Сегодня» считается по логической границе дня из настроек. Задача из `Soon`, чей день настал, переезжает в `Now`. Никакой отдельной логики просрочки.

### Привычки

Привычка — это JSON-файл в `Habits settings/` (имя, правило повторения, напоминания, цвет, рутина, цель, текст…) с постоянным id. Сегодняшняя привычка появляется строкой в `## Now` — это только вид. История — строки в `## Done` с `✅ дата` и `🆔` привычки:

| Отметка | В файле |
|---|---|
| Done | одна строка `[x]` |
| Partially | одна строка `[/]` |
| Twice | две строки `[x]` за один день |

Поставить галочку на сегодняшней строке привычки в Obsidian — то же, что отметить её в приложении.

Почему настройки привычек отдельными файлами, а не JSON в конце `Tasks.md`: правка привычки не трогает большой файл, поэтому меньше конфликтов в iCloud, а `Tasks.md` остаётся чистым и читаемым.

## Зеркало приложения

Файл повторяет то, что видно на экране. После каждого изменения `Now` переписывается: сначала задачи вне секций (со временем), затем секции пула заголовками `### Morning`, в том порядке, что на экране, со строками привычек. Пустые секции исчезают. То, что убрано «Not today», лежит в `Soon` до завтра.

**Синхронизация в обе стороны.** При каждом чтении файла (открытие приложения, pull-to-refresh) приложение сравнивает секции и порядок в `Now` с тем, что это устройство видело в последний раз (`day-look.json` в App Group). Если отличаются, значит, файл изменили руками или на другом устройстве: новые секции, порядок строк, принадлежность секциям и список «Not today» становятся приложением. При расхождении двух устройств побеждает версия, которую оставил iCloud, и приложение её подхватывает. Пока изменение не забрано, зеркало его не перезаписывает.

Первая строка файла `%% day 2026-11-04 %%` (комментарий Obsidian, в просмотре не виден) говорит, за какой день этот вид. Вид вчерашнего дня обратно не читается: секции каждого дня начинаются заново.

Рутины: свойство лежит в привычке (`options.timeOfDay` в JSON, `🌅` на сегодняшней строке — только для чтения глазами), порядок внутри рутины — в настройках приложения (`habits.morningRoutine`, `eveningRoutine`). Червяки (Select → Worm) — на один день, в приложении.

## Что упростилось

- Зависимостей между задачами и от событий больше нет: цепочки, блокировки, пикеры связей и проверка циклов удалены из приложения.
- Нет `due` с часовым поясом внутри, нет `date_modified`, YAML, по файлу на задачу.
- Нет экрана конфликтов iCloud для задач: каждая запись читает файл заново и меняет только свою строку, так что побеждает последняя запись, а чужие строки не страдают. Если два устройства правят файл без сети одновременно, iCloud оставит одну версию, и приложение подхватит именно её.

## Как устроено в коде

Домен и экраны не знают о формате: они говорят с протоколом `TaskStore` (`Data/Store/TaskStore.swift`).

| Файл | Что делает |
|---|---|
| `Data/TaskFile/TaskFileFormat.swift` | конфиг `task-file.json` |
| `Data/TaskFile/TaskEntry.swift` | одна строка ⇄ структура |
| `Data/TaskFile/TaskDocument.swift` | весь файл ⇄ разделы, группы, дерево строк; чужое сохраняется |
| `Data/TaskFile/TaskEntry+Item.swift` | строка ⇄ `TaskItem`, раздел по статусу |
| `Data/TaskFile/HabitFile.swift` | JSON привычки, отметки как строки в Done |
| `Data/TaskFile/TaskFileStore*.swift` | actor-хранилище: чтение, смена дня, запись, корзина, зеркало, импорт |
| `Domain/Day/Sections/DayLook.swift` | вид дня из файла: сравнение с прошлым и перенос в секции приложения |

`DayMirroring.mirror` зовёт `DerivedStatePublisher` после каждого изменения, `changedLook` — `SyncService` при каждом чтении. Запись атомарная, через `NSFileCoordinator`, и проверяется чтением обратно. Файл, который iCloud ещё не скачал, не считается отсутствующим: приложение ждёт его и не перезапишет пустым.

## Импорт из TaskNotes

Settings → Tasks → «From TaskNotes» → выбрать папку `TaskNotes`. Переносятся задачи, привычки с историей и папка Done. Папка `TaskNotes` только читается; задачи с уже существующими именами пропускаются, поэтому импорт можно повторить. Код адаптера TaskNotes (`Data/TaskNotes`) оставлен только для этого.
