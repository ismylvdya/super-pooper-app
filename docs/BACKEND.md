# Бэкенд: один файл задач

С ноября 2026 приложение работает на своём простом формате по образцу плагина Макса (`kudrmax/obsidian-task-tracker`). Папку `TaskNotes` и данные плагина приложение больше не читает.

## Где что лежит

В настройках выбирается папка `SuperPooperApp`. Приложение видит только её и **ничего не создаёт, если внутри нет `Task Manager`**: так случайно выбранная папка остаётся нетронутой.

```
SuperPooperApp/
  super-pooper-app-settings.json     настройки приложения
  Task Manager/
    Tasks.md                         все открытые задачи
    Done.md                          выполненные задачи и дни привычек
    Habits settings/
      a1b2c3d4.json                  настройки одной привычки
      Trash/                         удалённые привычки
```

Имена, заголовки разделов, галочки и значки — в `Resources/Config/task-file.json`, в коде их нет.

## Tasks.md

```markdown
## Today
- [ ] Побриться 📅 2026-11-04
### Morning
- [ ] 🚿 Холодный душ 📅 2026-11-04 🌅 morning 🔁 every-day 🆔 a9fc7aff
- [ ] Написать отчёт 📅 2026-11-04 ⏰ 14:00 ⏳ 60 ⚠️ 🐸 ▶️
    Текст задачи — строки с отступом.
    - [ ] Подзадача
## Next actions
- [ ] Отменить Sigma 📅 2026-11-05 ⚠️
- [ ] Ответ от банка ⏸️
- [ ] 🏋️ Зал 📅 2026-11-09 ⏰ 19:00 🔁 every-mon-sat 🆔 2e47c3dc
## Soon
## Someday
## Archive
## Trash
- [ ] Старое 🗑️ 2026-11-02
```

```markdown
## Done
- [x] Вазелин ✅ 2026-11-03
- [x] 🏋️ Отжимания ✅ 2026-11-03 🆔 2e47c3dc
```

Второй блок — это `Done.md`.

- **Раздел = лист.** `## Today` определяется только датой: задача с сегодняшней датой стоит там, остальные открытые — в `## Next actions`, ближний бэклог `## Soon`, дальний `## Someday`. Перенос в приложении переносит строку, перенос строки руками в Obsidian меняет лист.
- **Архив — отдельная секция.** Строка в `## Archive` сама никуда не переходит, какие бы дата и время у неё ни стояли.
- **Теги** не меняют лист: `▶️` начата, `⏸️` ждёт. Галочка: `[ ]` открыта, `[x]` выполнена; `[/]` бывает только у дней привычек в `Done.md`.
- **Поля — в конце строки**, каждое со своим значком: `📅` дата, `⏰` время, `🌐` часовой пояс (обычно пусто), `⏳` длительность в минутах, `🚨` будильник (`default`, id звука из `rules.json` → `alarms`, `sys-…` тон телефона, `custom-…` свой звук), `⚠️` high priority, `❤️` приятно, `🐸` требует энергии, `🌅` рутина, `🔼` родитель (если подзадача лежит в другом разделе), `🔁` правило повтора, `🕰️` просрочена, `✅` выполнена, `🗑️` удалена, `🆔` id (только у привычек и повторяющихся задач). Значок внутри названия остаётся названием: поля читаются только с конца строки.
- **Одно свойство даты вместо `due`.** Есть просто дата и просто время.
- **Подзадачи и текст** — строки с отступом под задачей.
- Всё остальное в файле (другие разделы, посторонние строки) сохраняется как есть. У обычной задачи `🆔` нет: приложение узнаёт её по самой строке. Старые `🆔` у обычных задач исчезают при первой записи.

### Смена дня

«Сегодня» везде считается по логической границе дня из настроек, а не по календарной полуночи. Строка `📅 2026-11-05 ⏰ 01:00` при границе 04:00 относится к логическому 4 ноября: она в `Today` этого дня и переносится только после 04:00 5-го.

При чтении файла незавершённая задача из `Today`/`Soon`, чей логический день прошёл, получает сегодняшнюю дату и теряет время (и часовой пояс, и будильник): она оказывается в пуле. Если время у неё было, она получает `🕰️` и оранжевый значок: время было назначено и прошло. Задача без времени просто ждёт дальше, без значка. `🕰️` снимается, когда задаче меняют дату или время. Задача из `Soon`, чей день настал, переезжает в `Today`.

Старый файл читается как есть: `## Soon` становится `## Next actions`, `## Half year` — `## Soon`, строки из `## Waiting` уходят в `## Next actions` с `⏸️`, `[/]` у задачи становится `▶️`, `## Done` переезжает в `Done.md`, `## Now` становится `## Today`, строки из `## Inbox` уходят в `## Soon`, `➕` исчезает при первой записи, `🔥` становится `⚠️`.

### Время

Время задачи одно: `⏰` в её строке. Блок на таймлайне, уведомление и будильник (`🚨`) берут его оттуда.

| Что случилось | Что в строке |
|---|---|
| Перетащили на таймлайн, поставили в листе даты | новые `📅` и `⏰` |
| Перетащили в пул | `⏰` убран, дата та же |
| Snooze с уведомления | `⏰` = момент повтора (длительность — в настройках, по умолчанию 30 минут) |
| Not today | у задачи со временем: то же время следующего логического дня; без времени: уходит в `Soon` без даты |
| Логический день кончился, задача не закрыта | дата = новый день, `⏰`, `🌐` и `🚨` убраны, `🕰️` если время было: задача в пуле |

Два исключения из «одно время»:

- **Просроченный блок в течение дня.** Время прошло, задача не закрыта: на таймлайне блок едет за линией «сейчас», а в строке остаётся своё время.
- **Привычка.** Её времена на все дни лежат в JSON (`reminderTimes`). Перенос блока или Snooze меняет только сегодня: это хранится в состоянии дня (`TimeMove`, не в vault), а в файл попадает как `⏰` на сегодняшней строке в `Today`. Завтра снова как в JSON. Время, поправленное в этой строке руками, при следующей синхронизации переезжает на таймлайн и в уведомление, только на сегодня; настройки привычки не меняются.

### Будильник

Время с `🚨` звонит через AlarmKit: на экране название задачи, кнопка Snooze и системный слайдер. Слайдер отмечает задачу выполненной, Snooze пишет в строку время «сейчас + минуты из настроек» и ставит новый будильник. Обычного уведомления рядом с будильником нет. Если будильники в системе запрещены, вместо него приходит обычное уведомление со звуком.

Подпись слайдера («slide to stop») задаёт iOS: начиная с iOS 26.1 приложение не может её менять, на 26.0 там написано Done. Свои звуки добавляются в настройках, конвертируются в `.caf`, обрезаются до 30 секунд и лежат в `Library/Sounds` приложения, так что на другое устройство сами не переедут.

### Not today и Tomorrow

Not today у задачи снимает дату и время: она остаётся в `## Next actions` без даты и в пул не попадает. Tomorrow у привычки ставит её строку в `## Next actions` на завтра. Если своего дня завтра по правилу нет, она завтра стоит в пуле без времени и с `🕰️`. Так же в пуле с `🕰️` оказывается то, что день оставил незавершённым со временем.

В день задачу приводит дата. Новая задача без даты создаётся в `## Next actions`. В начале каждого дня все задачи без даты из этого листа получают сегодняшнюю дату и встают в `## Today`, а значит, и в Morning Review, открыл ты обзор или смахнул его. Строка без даты в `## Today` (из старого файла или написанная вручную) тоже получает сегодняшнюю дату.

### Open in Obsidian

Открывает `Tasks.md` на строке задачи и подсвечивает её, у привычки это её открытая строка. Делает это плагин из `obsidian-plugin/`, без него ссылка файл не откроет. Файл при этом не меняется. Старая метка `^open` в конце строки при чтении не становится частью имени и исчезает при следующей записи.

### Имена

Имя занято только открытой задачей или привычкой. Строки в `Done.md` и `## Trash` имя не занимают: новая задача с тем же именем создаётся без номера. Две одинаковые открытые строки пока нельзя: приложение различает открытые задачи по имени, новая получит номер.

### Привычки и повторяющиеся задачи

Настройки — JSON-файл в `Habits settings/` (имя, правило повтора, напоминания, какие из них будильники, цвет, рутина, цель, текст…) с постоянным id. В `Tasks.md` у привычки ровно одна открытая строка, её пишет приложение:

- **Сегодня её день и он не закрыт:** строка в `## Today`, `📅` сегодня, `⏰` сегодняшнее время.
- **Иначе:** строка в `## Next actions`, `📅` ближайший день по правилу, `⏰` первое время из настроек.

`🔁` показывает правило одним словом: `every-day`, `every-6-days`, `every-mon-sat`, `every-2-weeks-mon`, `every-15-of-month`, `every-last-day-of-month`, `every-last-sat-of-month`, `every-year-03-21`. Само правило живёт в JSON, строка только показывает его. Начала и конца у повтора нет: начало — ближайший подходящий день, конец бесконечен.

**Выполнение.** В `Done.md` появляется копия с датой без времени, а открытая строка получает следующую дату. У привычки Twice после первого выполнения строка остаётся в `## Today`, после второго уходит дальше, и в `## Done` две одинаковые строки за день.

**Просрочка.** День привычки прошёл, она не закрыта:

- На новый день правило её тоже ставит: строка просто пишется заново, никакой просрочки.
- Не ставит: строка переезжает в `## Today` пула без времени, с `🕰️`, и стоит там, пока её не выполнят или не настанет следующий день по правилу.

**Имя.** Строки в `Done.md` связаны с привычкой через `🆔`. При переименовании они сохраняют старое имя, файл целиком не переписывается.

История привычки — строки в `Done.md` с `✅ дата` и `🆔` привычки:

| Отметка | В файле |
|---|---|
| Done | одна строка `[x]` |
| Partially | одна строка `[/]` |
| Twice | две строки `[x]` за один день |

Поставить галочку на сегодняшней строке привычки в Obsidian — то же, что отметить её в приложении.

Почему настройки привычек отдельными файлами, а не JSON в конце `Tasks.md`: правка привычки не трогает большой файл, поэтому меньше конфликтов в iCloud, а `Tasks.md` остаётся чистым и читаемым.

## Зеркало приложения

Файл повторяет то, что видно на экране. После каждого изменения `Today` переписывается: сначала задачи вне секций (со временем), затем секции пула заголовками `### Morning`, в том порядке, что на экране, со строками привычек. Пустые секции исчезают. То, что убрано «Not today», лежит в `Soon` до завтра.

**Синхронизация в обе стороны.** При каждом чтении файла (открытие приложения, pull-to-refresh) приложение сравнивает секции, порядок и времена привычек в `Today` с тем, что это устройство видело в последний раз (`day-look.json` в App Group). Если отличаются, значит, файл изменили руками или на другом устройстве: новые секции, порядок строк, принадлежность секциям и список «Not today» становятся приложением. При расхождении двух устройств побеждает версия, которую оставил iCloud, и приложение её подхватывает. Пока изменение не забрано, зеркало его не перезаписывает.

Первая строка файла `%% day 2026-11-04 %%` (комментарий Obsidian, в просмотре не виден) говорит, за какой день этот вид. Вид вчерашнего дня обратно не читается: секции каждого дня начинаются заново.

Рутины: свойство лежит в привычке (`options.timeOfDay` в JSON, `🌅` на строке — только для чтения глазами), порядок внутри рутины — в настройках приложения (`habits.morningRoutine`, `eveningRoutine`). Червяки (Select → Worm) — на один день, в приложении.

## Что упростилось

- Зависимостей между задачами и от событий больше нет: цепочки, блокировки, пикеры связей и проверка циклов удалены из приложения.
- Нет `due` с часовым поясом внутри, нет `date_modified`, YAML, по файлу на задачу.
- Нет экрана конфликтов iCloud для задач: каждая запись читает файл заново и меняет только свою строку, так что побеждает последняя запись, а чужие строки не страдают. Если два устройства правят файл без сети одновременно, iCloud оставит одну версию, и приложение подхватит именно её.

## Как устроено в коде

Домен и экраны не знают о формате: они говорят с протоколом `TaskStore` (`Data/Store/TaskStore.swift`).

| Файл | Что делает |
|---|---|
| `Data/TaskFile/TaskFileFormat.swift` | конфиг `task-file.json` |
| `Data/TaskFile/TaskEntry.swift` | одна строка ⇄ структура |
| `Data/TaskFile/TaskDocument.swift` | весь файл ⇄ разделы, группы, дерево строк; чужое сохраняется |
| `Data/TaskFile/TaskEntry+Item.swift` | строка ⇄ `TaskItem`, раздел по статусу |
| `Data/TaskFile/HabitFile.swift` | JSON привычки, отметки как строки в Done |
| `Data/TaskFile/RepeatTag.swift` | правило повтора одним словом для `🔁` |
| `Data/TaskFile/TaskFileStore+Repeats.swift` | открытая строка привычки, её следующий день и просрочка |
| `Data/TaskFile/TaskFileStore*.swift` | actor-хранилище: чтение, смена дня, запись, корзина, зеркало, импорт |
| `Domain/Day/Sections/DayLook.swift` | вид дня из файла: сравнение с прошлым и перенос в секции приложения |

`DayMirroring.mirror` зовёт `DerivedStatePublisher` после каждого изменения, `changedLook` — `SyncService` при каждом чтении. Запись атомарная, через `NSFileCoordinator`, и проверяется чтением обратно. Файл, который iCloud ещё не скачал, не считается отсутствующим: приложение ждёт его и не перезапишет пустым.

## Импорт из TaskNotes

Settings → Tasks → «From TaskNotes» → выбрать папку `TaskNotes`. Переносятся задачи, привычки с историей и папка Done. Папка `TaskNotes` только читается; задачи с уже существующими именами пропускаются, поэтому импорт можно повторить. Код адаптера TaskNotes (`Data/TaskNotes`) оставлен только для этого.
