# SuperPooper — справочник

Документ для человека и для нового агента (Claude Code). Сначала — что это и где что лежит, потом — как устроена логика, потом — рецепты и частые поломки.

## 1. Что это и зачем

SuperPooper — iPhone-приложение-оболочка над тремя системами. Своей базы задач у него **нет**:

| Что | Где живёт | Что делает приложение |
|---|---|---|
| Задачи, привычки, периодические дела | `.md`-заметки TaskNotes в папке `TaskNotes` vault Obsidian (iCloud Drive); приложению выдаётся доступ только к этой папке | читает, точечно правит frontmatter и текст, создаёт новые дела (утренний разбор) и привычки (вкладка Habits) |
| Жёсткие события («якоря») | Apple Calendar, календари выбраны в настройках | только читает, показывает на таймлайне |
| «Вспомнить в X» | Apple Reminders, листы выбраны в настройках | только читает, шлёт своё уведомление |
| Inbox | отдельный лист Reminders | не читает; ярлык «📥 New in inbox» на иконке приложения запускает шорткат пользователя (Settings → Today → Quick actions), который добавляет туда напоминание |
| Ручной порядок пула, Skip today | App Group, только на сегодня | потеря не страшна |
| Настройки, снимок для виджетов, бэкапы | App Group (JSON) | общие с виджетами; можно стереть |

Вкладки: **Today** · **Habits** · **Lists** (группы списков из `lists.json`: «By feel» — приятное, требует энергии, быстрое; «All statuses» — по списку на каждый статус TaskNotes; «+» у дела переводит его в `this_week`, «+» в панели создаёт новое, лупа ищет по всем делам) · **Settings** (внутри: Tasks, Habits, Version conflicts, Trash, Clock). Главный экран Today: сверху **пул** — дела дня без времени (просрочиться не могут), ниже **таймлайн** с линией «сейчас»: события, всё со временем и цепочки дел, привязанные к событиям. Без streak'ов, без почасового планирования. Телефон боком (`PhysicalBottom`): кнопки остаются на своих местах физического экрана — вкладки колонкой вдоль физического низа (в том же физическом порядке), кнопки Today колонкой вдоль физического верха, стрелки дня смотрят туда же, куда стоя; день назван двумя буквами дня недели.

Проект — обычный `SuperPooper.xcodeproj` с **синхронизируемыми папками** (Xcode 16+): новый файл в папке сам попадает во все таргеты этой папки, `project.pbxproj` править не нужно.

Слои и направление вызовов: **экраны → состояние (`AppModel`) → домен (`Domain/`) → репозитории (`Data/Repositories`) → источники (файлы, EventKit, уведомления)**. Экран не читает файлы и не зовёт EventKit. Домен — чистые функции: данные и «сейчас» на входе, результат на выходе. Data не собирает тексты интерфейса (ошибка YAML приходит как `FrontmatterError`, слова — `Features/Common/FrontmatterErrorText`), модель не играет вибрацию (это делают экраны и `TaskActionHandler` по `actions.json`). Один файл — одна ответственность (вспомогательный тип — в свой файл рядом).

Время — только из `Clock`; календарь — один (`AppCalendar.make()`), у приложения и виджетов одинаковый, во вью — `@Environment(\.calendar)`. Логический день момента — `DayContext.logicalDay(of:)` (сравнение по циферблату, поэтому ночи перевода часов не сдвигают границу).

## 3. Карта конфигов: чтобы изменить X — правь Y

Все конфиги — `Resources/Config/`. Они проверяются при запуске: опечатка в ключе — экран с именем файла и путём к ключу, а не падение.

| Чтобы изменить… | Правь |
|---|---|
| Раскладку Today (пул сверху/слева/страницами, доли места, порядок блоков) | `layouts/today-stacked.layout.json` (пул сверху), `layouts/today-side-by-side.layout.json` (пул слева) и `layouts/today-paged.layout.json` (по умолчанию: пул и таймлайн — две страницы на весь экран, `"paged": true`, `"peek"` — токен размера видимого края соседней страницы, у блока `"peekChip"` — какая часть последнего чипа его строк видна, пока открыта другая страница: у пула 0.5): `axis` (`vertical`/`horizontal`), `blocks` (`size`: `fit` или `fill` + `weight`), `spacing` (имя токена). Какой из них используется — настройка Settings → Today screen, для телефона боком — отдельная «Today in landscape»; у виджета Today свой выбор и только первые два (`TodayArrangement.forWidget`) |
| Отступы, скругления, размеры, прозрачности, длительности, шрифты, цвета (светлые и тёмные) | `tokens.json`. Новый токен = ключ в JSON + `case` в `DesignSystem/Tokens/TokenKeys.swift` |
| Иконки SF Symbols вне действий | `icons.json` (+ `case` в `Core/Config/IconSet.swift` для нового) |
| Действия (название, иконка, вибрация, подтверждение) и состав меню/уведомлений | `actions.json` (`actions` и `menus`): меню дела и привычки в пуле, страницы дела, дня привычки в Habits и истории (`habitDay`), напоминания (`reminderContext`) и события (`eventContext`) на таймлайне. Новое меню — `case` в `ActionMenu` (`Core/Config/ActionRegistry.swift`), отсутствующее меню или действие останавливает запуск с ошибкой конфига |
| Порядок критериев сортировки пула | `sort.json` → `pool` (список; переставить строки = поменять приоритет) |
| Имена полей TaskNotes и значения статусов/приоритетов | `field-mapping.json` |
| Включить/выключить функцию | `feature-flags.json` |
| Группы и списки вкладки Lists (группа: название и списки; список: название, иконка — ключ `icons.json`, статусы, `pleasant`, `needEnergy`, `maxEstimate`) | `lists.json` |
| Пороги и правила: оценка по умолчанию, подписи оценок (`2 min`…`dohuya`), лимит уведомлений, горизонт, окно поиска событий, таймаут и шаг опроса iCloud, задержки (запись заметки настроек, реакция на изменения в Calendar), число бэкапов, шаги виджетов | `rules.json` |
| Пределы степперов и слайдеров настроек (часы до/после, размер колокольчика, шрифты, прозрачность, интервал и число повторов) | `rules.json` → `limits` (`min`, `max`, `step`) |
| С чего начинается новое значение: время по умолчанию, отступ следующего напоминания привычки, задержка сохранения описания, конец повторения через N дней / после N раз | `rules.json` → `editing` |
| Значения настроек по умолчанию (папка задач, тег, граница дня, час энергии, раскладка таймлайна…) | `defaults.json` |

Пример из манифеста: «пул сверху, таймлайн снизу» → «пул слева, таймлайн справа» = заменить `"axis": "vertical"` на `"axis": "horizontal"` в `today-stacked.layout.json` (проверено, см. `PROGRESS.md`). Пользователь переключает раскладки в настройках, не трогая конфиги.

Пользовательские настройки хранятся в App Group (`settings.json`) и при чтении **накладываются на `defaults.json`**: новые поля из новой версии сразу получают значения по умолчанию.

Общая часть настроек (всё, кроме папки, календарей/списков этого устройства и онбординга) лежит в vault — заметка `SuperPooper Settings.md` рядом с папкой задач. **Каждая настройка — отдельное свойство frontmatter**, имя — путь в JSON (`SettingsProperties`):

```yaml
---
today.arrangement: paged
timeline.hoursBefore: 2
clock.prefix: "12"          # строка, похожая на число, — в кавычках
habits.morningRoutine:
  - Душ
---
```

Заметки старых версий держали JSON в блоке ```` ```SuperPooperApp ````: он читается (свойства важнее) и удаляется при следующей записи. Текст заметки под свойствами приложение не трогает.

## 4. Как устроен день

Код: `Domain/Day/DayBuilder.swift` и соседи. Всё считается заново от «сейчас» (раз в минуту на экране, на каждую запись в виджете).

### 4.1. Граница дня
`day.boundary` (по умолчанию 04:00): до неё ещё «вчера». `DayContext.today` — логическая дата. Время до границы относится к концу логического дня: привычка в 00:30 стоит в конце сегодняшнего таймлайна (`DayContext.moment`), задача с `due` на 01:00 следующей даты — сегодняшняя (`DayContext.logicalDay`).

### 4.2. Что попадает в день
- задачи `this_week` без `recurrence`, кроме датированных позже сегодняшнего логического дня (Tomorrow, пятница): такая ждёт своего дня и видна на его странице; просроченная остаётся в сегодня;
- задачи, отмеченные `done` сегодня (`completed_date` = сегодня) — видны как сделанные до конца дня;
- повторяющиеся задачи, у которых по `recurrence` есть экземпляр сегодня (статус не важен), или уже отмеченные сегодня;
- не попадают: Skip today, `waiting`, `half_year`, `someday`, `archived`, сделанные раньше.
- **Другой день** (вчера, завтра и дальше на Today): дела `this_week` с датой этого дня и привычки с `show_in_today`, у которых по `recurrence` есть экземпляр в этот день («каждые 6 дней» — только в свои дни). «Прошло» и блокировка — от настоящего «сейчас».

### 4.3. Пул и таймлайн
- **Таймлайн**: события выбранных календарей; задачи и привычки со временем (`due` с временем: у обычной задачи — на сегодня, у привычки — время дня); напоминания Reminders; задачи, связанные с событием через `previous_event`/`next_event`, **и всё, что связано по `previous_task` с чем-то на таймлайне — прямо или косвенно, в любую сторону**: идущее после события или задачи со временем — за ним, нужное до него — от «сейчас».
- **Пул**: всё остальное, включая задачи, связанные только друг с другом (вся группа связей — в пуле).
- **Перетаскивание** (`TaskScheduling`, `TaskDragState`): удержать строку и тянуть (без «трёх полосок»; удержание без движения — меню). В пуле — меняет порядок (тот же ручной порядок, что в утреннем разборе). Задача, брошенная на таймлайн, получает `due` с датой и временем точки (шаг — `rules.json` → `timeline.dropStepMinutes`), а с ним и уведомление; минуты точки видны у колонки часов. Задача со своим временем, брошенная в пул, теряет время (дата остаётся). Привычки на таймлайн и с него не переносятся: время в TaskNotes относилось бы ко всем их дням. На страницах край соседней страницы перелистывает её при перетаскивании и по тапу. Только на сегодня и в одноколоночном таймлайне (не в «двух половинах»).
- **Цепочки** (`ChainLayout`, якорь — событие или задача со своим временем): «до» (`next_event` или предшественник) — подряд от «сейчас»; «после» (`previous_event` или последователь) — от конца якоря или от «сейчас», если он закончился. Невыполненные идут за курсором и сдвигаются вместе с «сейчас», сделанные складываются перед курсором. Длительность — `time_estimate` (пусто = 15 мин).
- **Отрисовка** (`DayTimelineView`): высота блока — по оценке, но не меньше строки текста; блок, не пересекающийся с предыдущим по времени, но наезжающий визуально, сдвигается ниже; реально пересекающиеся — рядом в колонках, как в Calendar.

Пример: сейчас 11:30, «Подготовить вопросы папе» (`next_event: Call with dad 19:00`) → 11:30–11:45; «Распечатать вопросы» (`previous_task: Подготовить…`) → 11:45–12:00, заблокирована; «Записать итоги разговора» (`previous_event: Call with dad`) → 20:00, заблокирована до конца звонка.

### 4.4. Блокировка (`BlockingEvaluator`)
- Задача заблокирована, пока не сделаны все `previous_task`: обычная — статус `done`/`archived`; повторяющаяся — сегодня отмечена или пропущена Skip today; повторяющаяся без экземпляра сегодня не блокирует.
- `previous_event` блокирует до окончания события.
- Ссылка на несуществующую задачу не блокирует (значок проблемы).
- Циклы разрываются (одна связь игнорируется), участникам — значок проблемы.
- Заблокированная задача выглядит как обычная, только с чипом связи (🔗); в пуле она всегда после своих предшественников.

### 4.5. Сортировка пула (`PoolSorter`, порядок — `sort.json`)
1. `habitsFirst` — привычки без времени первыми, в порядке их связей;
2. `dueToday` — `due` сегодня;
3. `highPriority`;
4. `nearestDueThisWeek` — ближайший `due` на этой неделе;
5. `energyBeforeEnergyHour` — `need_energy` до часа энергии выше, после — ниже;
6. `unpleasantFirst` — `pleasant: false` раньше;
7. `shortFirst` — короткая оценка раньше;
8. `olderFirst` — старше `date_created` раньше.

Поверх: задача никогда не выше своих `previous_task` (стабильная топологическая сортировка); сделанные сегодня — в конце. Сабтаск (`projects` → родитель) стоит сразу под родителем, с отступом (`spacing.subtaskIndent`), при любой сортировке и ручном порядке (`SubtaskNesting`); если родителя в пуле нет — стоит по сортировке.

**Ручной порядок** (утренний разбор): пока ничего не перетащено, порядок пересчитывается после каждой правки. После первого перетаскивания порядок фиксируется на сегодня (`day-state.json`); новые задачи встают после своего соседа по автосортировке; «Reset to auto» возвращает авто.

### 4.6. Автоперевод
При открытии и pull-to-refresh задачи `half_year`/`someday` без `recurrence` с `due` с сегодня по воскресенье получают `this_week` (перед этим — бэкап). Список статусов — `rules.json` → `day.autoPromoteFrom`. Статусы приложение никогда не понижает.

### 4.7. Привычки
- **Вкладка Habits**: список активных привычек (порядок — перетаскиванием, хранится в настройках `habits.order`), круглая кнопка дня (тап — Done → Twice → снять, долгое нажатие — меню), строка «N/цель this week», «+» — новая привычка, внизу архив привычек. Страница привычки: имя, история (недели до старта привычки, любой день отмечается), статистика, Color / Show in Today / Harmful / Part of the day / Twice a day, правило пропусков (Allowed skips или Weekly goal), повторение, напоминания, описание (= тело заметки).
- Чекбоксы привычек везде одинаковые (SF Symbols, `icons.json` → `habitOpen/Done/Partial/Twice/NotScheduled`).
- В Today попадает только привычка с `show_in_today` (нет ключа = да) и не в архиве. У новой привычки флаг включён (Settings → Habits → «Show new habits in Today»). Уведомления приходят независимо от этого флага.
- Уведомление живёт свой логический день: смахнутое возвращается без звука, пока дело или привычка не отмечены, но на границе дня уходит. Убирают его синхронизация приложения (по таймеру на границе, если приложение открыто; при открытии; фоновое обновление просится не позже границы) и виджеты, которые перезагружаются на границе и при закрытом приложении. Запланировать удаление доставленного уведомления в iOS нельзя, поэтому без виджетов и фонового обновления вчерашнее уйдёт при первом запуске после границы.
- Статистика (`Domain/Habits/HabitStats.swift`): серии, доли за 7/30 дней и всё время, счётчики, по дням недели и месяцам. Правила подсчёта — `DECISIONS.md` D-031.
- Привычка = заметка со `status: habit` (читается как привычка и любая заметка с `recurrence`). Дни задаёт только `recurrence` (RRULE TaskNotes); без правила — каждый день. `due` у привычки не учитывается ни в днях, ни в сортировке пула.
- Время дня — `reminder_times` (список `HH:mm`, можно несколько, например для «дважды в день»); старый `due` со временем читается как единственное напоминание. Каждое время — свой блок таймлайна и своё уведомление; без напоминаний привычка стоит в пуле.
- Дело и привычку нельзя превратить друг в друга. Правило правится редактором как в Apple Calendar (`Domain/Recurrence/RecurrenceDraft.swift`).
- В пуле: долгое нажатие — Done, Partially, Twice, Skip today. Уведомление — Done, Partially, Skip today; второй Done за день при двух напоминаниях = Twice.
- Done → дата в `complete_instances`; Partially → в `complete_instances` и `partial_instances`; Twice → в `complete_instances` и `twice_instances`. Снятие — убирает из всех трёх.
- Skip today в заметку не пишется (только `day-state.json` до конца дня).
- `due` у привычек приложение **не двигает** (в отличие от TaskNotes, который при отметке переносит scheduled на следующий экземпляр) — см. DECISIONS.

### 4.8. RRULE (`Domain/Recurrence`)
Поддерживается то, что генерирует TaskNotes: `DTSTART` (дата или дата-время; «Z» — фиктивная, время локальное, как в TaskNotes), `FREQ=DAILY|WEEKLY|MONTHLY|YEARLY`, `INTERVAL`, `BYDAY` (в т.ч. `2MO`, `-1FR`), `BYMONTHDAY` (в т.ч. отрицательные), `BYMONTH`, `COUNT`, `UNTIL`, `WKST`. Без `DTSTART` точка отсчёта — дата из `due`, затем `date_created`. Незнакомое правило — задача видна каждый день со значком проблемы (как в TaskNotes). Поведение сверено с кодом TaskNotes 4.13.8 / rrule.js на 9000 случайных правил.

## 5. Формат заметки (для Claude-скилла)

- **Название задачи = имя файла** без `.md`. Поля `title` нет.
- Папка задач — `TaskNotes/Tasks` (настройка, от корня vault; если приложению выбрана сама папка `TaskNotes`, используется `Tasks` внутри неё), признак задачи — тег `🔫делишка` в `tags`.

```yaml
---
tags:
  - 🔫делишка
status: this_week            # this_week | half_year | someday | waiting | done | archived | habit
priority: high               # high | none
due: 2026-10-23T16:00        # YYYY-MM-DD или YYYY-MM-DDTHH:mm (локальное время)
time_estimate: 15            # минуты: 2 | 15 | 60 | 240; пусто = 15
previous_task:               # задачи, которые делаются ДО этой (блокировка)
  - uid: "[[Купить батарейки]]"
    reltype: FINISHTOSTART
previous_event: "8A1F…:A2B3…|Call with dad|2026-10-23T19:00:00+02:00"   # после события
next_event: "…"              # до события (тот же формат)
projects:                    # сабтаск: родительская заметка (как в TaskNotes)
  - "[[Ремонт]]"
need_energy: true
pleasant: false
recurrence: DTSTART:20261001T000000Z;FREQ=DAILY     # правило привычки
superpooper: '{"habit_color":"#34C759","reminder_times":["09:00","21:00"],"show_in_today":false,"weekly_goal":5}'
                             # настройки приложения у дела или привычки — одно свойство с JSON (см. ниже)
complete_instances: [ ... ]  # дни с любой отметкой
partial_instances: [ ... ]   # дни с Partially (они же есть в complete_instances)
twice_instances: [ ... ]     # дни с Twice (они же есть в complete_instances)
completed_date: 2026-10-23   # ставится при отметке обычной задачи вместе с status: done
date_created: 2026-10-20T09:12:44.123+02:00
date_modified: 2026-10-22T18:01:02.456+02:00         # обновляется при каждой записи
---
Текст заметки.
```

- **Настройки приложения** у дела или привычки — одно свойство `superpooper` с JSON (имя и состав — `field-mapping.json` → `itemSettings`). Ключи внутри: `reminder_times` (времена дня, несколько можно), `show_in_today` (нет ключа = да), `habit_color`, `harmful`, `time_of_day` (`morning` | `day` | `evening`), `twice_a_day`, `twice_counts_double` (Twice = 2 в цели и долях), `weekly_goal` (N раз в неделю), `allowed_skips` (пропуски подряд, если нет `weekly_goal`). Заметки старых версий держат их отдельными свойствами с теми же именами: они читаются, а при следующем изменении любой настройки переезжают в JSON. Скилл может писать любой из вариантов; JSON важнее отдельного ключа.
- `previous_task` читается также как строки `"[[Имя]]"` и строки без скобок; пишется объектами `{uid: "[[Имя]]", reltype: FINISHTOSTART}`, как в TaskNotes. «Next tasks» в файле не хранится — это `previous_task` других задач.
- **Ссылка на событие**: строка `eventIdentifier|название|начало ISO 8601` (с часовым поясом). Название может содержать `|` — делятся только первый и последний разделитель. Поиск: по `eventIdentifier` в тот же день (у повторяющихся событий id общий, ближайшее по времени начало), затем по названию и точному времени начала, иначе — «event not found» (значок, связь игнорируется). Скилл может писать любой `eventIdentifier` (например, `skill`), если название и время точные.
- **Сабтаски** — по-тасконотовски: отдельные заметки-задачи, у которых в `projects` есть ссылка на родителя. Приложение добавляет ссылку при создании сабтаска и переименовывает её вместе с родителем; остальные записи `projects` не трогает.
- Приложение **не трогает**: `deadline`, `skipped_instances`, `recurrence_anchor` (не удаляет), тег `archived`, `contexts`, `timeEntries`, `pomodoros`, любые незнакомые ключи, комментарии и тело (байт-в-байт, покрыто тестами).

## 6. Запись в файлы

`Data/Repositories/VaultTaskRepository.swift`: чтение и запись через `NSFileCoordinator`, атомарно; меняется **только** нужный ключ (`Data/Frontmatter/FrontmatterDocument.swift` — свой редактор подмножества YAML, который Obsidian пишет) плюс `date_modified`. Списки (`*_instances`, `previous_task`) меняются **дельтами** по свежепрочитанному файлу: отметить один день, добавить/убрать/переименовать одну связь; записи, которые приложение не поняло, остаются. Текст, который не разбирается как frontmatter, не записывается никогда.

- Файл изменили с момента чтения (Mac, Claude-скилл): правка применяется к свежей версии, меняя только свои ключи; если тот же ключ изменён и там, сверху жёлтая плашка (`WriteConflict`).
- **Конфликтные версии iCloud приложение само не разрешает.** После синка — жёлтая плашка «Version conflict in …»; тап открывает Settings → Version conflicts → заметка: все версии с устройством и временем, полный текст, «Keep this version» (перед этим бэкап). Пока конфликт не разрешён, правки ложатся в текущую версию файла.
- Удаление — в `.trash` в выбранной папке (обычно `TaskNotes/.trash`), после диалога и бэкапа. Экран Settings → Trash: просмотр, восстановление в папку задач, удаление навсегда с подтверждением.
- Переименование — файл + `previous_task` у задач, которые на неё ссылаются (после бэкапа). Ссылки в тексте других заметок не переписываются.
- Каждое изменение проверяется: записанный текст читается обратно, у перемещения — файл на новом месте и нет на старом. Не подтвердилось — красная плашка `error.write.notConfirmed`; зелёные плашки (создано, переименовано, удалено, в архив, восстановлено) появляются только после подтверждения.
- Бэкапы: App Group → `SuperPooper/Backups/<время>-<причина>/`, хранится `rules.json → backups.keepCount` последних.

## 7. Как добавить поле задачи

1. `Resources/Config/field-mapping.json` → `fields` (+ свойство в `Core/Config/FieldMapping.swift`).
2. Свойство в `Domain/Model/TaskNote.swift` и `case` в `Domain/Model/TaskFieldChange.swift` (+ строка в `applying`).

4. Редактирование — строка в `Features/TaskPage/TaskPropertiesSection.swift` (и чип в `Features/MorningReview` при желании), тексты — `Localizable.xcstrings`.

6. Тесты: чтение/запись в `Tests/Data`, логика в `Tests/Domain`.

## 10. Частые поломки

| Симптом | Причина | Что делать |
|---|---|---|
| «Can’t open the vault folder anymore» | bookmark устарел (переименовали/переместили папку, переустановка) | Settings → Tasks → Sources → TaskNotes folder → выбрать заново |
| Жёлтое «The app has access to the whole vault» | выбран весь vault, а не папка `TaskNotes` (старая настройка) | выбрать папку `TaskNotes` заново |
| Плашка «Version conflict in …» | iCloud хранит две версии заметки | тапнуть плашку и выбрать версию |
| Задача пропала, в проблемах «Not downloaded from iCloud yet» | файл выгружен с телефона, не скачался за таймаут | открыть «Файлы», дождаться iCloud, потянуть вниз; таймаут — `rules.json → vault.downloadTimeoutSeconds` |
| Жёлтая плашка «was also changed elsewhere» | один ключ правили на Mac и iPhone | проверить значение: записана правка с iPhone; бэкап — в App Group |
| Заметка не видна, «Broken YAML» | ошибка в frontmatter (незакрытая кавычка/скобка, табы) | исправить в Obsidian; приложение такие заметки пропускает |
| Событий нет на таймлайне | нет доступа к Calendar или не выбраны календари | Settings → Sources: Calendar access, Anchor calendars |
| «Event not found» у задачи | событие удалили/перенесли на другой день | выбрать событие заново на странице задачи |
| Виджет «Open SuperPooper once…» | нет снимка в App Group или виджет не видит группу | открыть приложение; проверить App Group у обоих таргетов (TRANSFER.md) |
| Экран «Config error» | опечатка в `Resources/Config/*.json` (в том числе имя блока, токена отступа или `peek` в раскладке Today, нет меню или действия в `actions.json`) | исправить ключ, указанный на экране |

## 11. Процесс (из манифеста)

- «Релизь» = закоммитить с описанием всего, что появилось с прошлого коммита, и выпустить релиз (git-тег) с буллет-списком всего, что появилось с прошлого релиза.
- Коммиты и релизы — только по команде пользователя.
- После изменений — собрать и поставить в симулятор; в симулятор заходить, только чтобы найти баг, о котором сказал пользователь.
